# ビジネスイベント/セミナー ポータル 在庫実測レポート

**調査日:** 2026-09-09
**対象:** 系統A 10自治体（特定創業支援等事業）／系統B 8機関（補助金・支援機関イベント）
**方法:** 実地取得。1リクエストにつき3秒ウェイト、直列アクセスのみ、一般的なChromeのUA。robots.txtのDisallow配下は未アクセス。PDFはURL記録のみ。
**原則:** ページに書かれていない項目は "unknown" / "記載なし"。推測で数値を作っていない。

構造化データは [inventory-survey.json](inventory-survey.json) を参照。

## 0. 結論の要約

**この在庫でポータルは成立する。ただし「自治体を広く薄く集める」設計では成立しない。**

- 系統A（自治体）10件の**募集中は合計16件、平均1.6件/自治体**。うち具体的な開催日を持つものは**8件（0.8件/自治体）**。
- 系統B（支援機関）は桁が違う。**東京商工会議所1機関だけで398件掲載、うちポータル関連（起業・創業＋補助金・助成金）が最大52件**。
- つまり**在庫の重心は自治体ではなく支援機関側にある**。自治体ページの多くは「事業カタログ」であって、イベント一覧ではない。
- 一方で**規模の大きい機関＝創業在庫が多い、ではない**。東京都中小企業振興公社は76件を掲載しているが「創業・新事業」はわずか2件だった。

## 2. 全国への外挿（系統A）

### 前提（すべて明記）

1. **母数は認定市区町村 約1,459**（依頼で与えられた数値）。
2. **サンプル10自治体は大都市に強く偏っている**（政令市5・特別区1・中核市2・中規模市2）。全国1,459の大半は小規模自治体であり、単純平均は過大になる。
3. 「年間開講回数」を数えられたのは**7自治体のみ**（横浜・川崎・板橋・大阪・名古屋・松本・川口）。福岡・那覇・高松は頻度の記載がなく**unknown**。
4. 板橋区は「年5回」、名古屋市は「年2期」、川口市は「年4回＋年4回程度＋全5回」等、**ページに頻度が明記されている場合のみ採用**した。
5. 募集期間は川崎・名古屋・板橋の実例から**1コースあたり概ね6週間**と仮定した。

### 年間開講回数の推定

サンプル7自治体の年間開講回数（日付を伴うコース単位）:

| 自治体 | 年間開講回数 | 根拠 |
|--------|------------|------|
| 横浜市 | 約2 | 日付を持つスクール2件（各々の年間回数は不明） |
| 川崎市 | 9 | 実施期間を持つ事業を計数 |
| 板橋区 | 5 | 「年間5回実施（昼間3・夜間2）」と明記 |
| 大阪市 | 8 | 実施時期のめやす月から算出（5/10/1月＝3、8月＝1、6/11月＝2 ほか） |
| 名古屋市 | 2 | 第1期・第2期の年2期制 |
| 松本市 | 1 | 年1回の松本地域創業スクール |
| 川口市 | 10 | 年4回＋年4回程度＋全5回×1＋年1回 |
| **平均** | **5.3** | 7自治体 |

### 層別外挿

サンプルの大都市偏りを補正するため、2層に分けて外挿する。

- **大規模層 約200自治体**（政令市20＋特別区23＋中核市62＋その他大都市 約95）: 5.3回/年
  → 200 × 5.3 = **約1,060回/年**
- **中小規模層 約1,259自治体**: 1〜2回/年（サンプル中の中規模市＝松本市が1回/年である点を根拠にした。ただし**この層の実測は松本市1件のみで、外挿の最大の弱点**）
  → 1,259 × 1.5 = **約1,889回/年**

**年間コース開講数：約2,000〜4,000回**（中心値 約2,950回）

### 同時募集中件数の推定

**方法1（開講回数×募集期間）:** 2,950回/年 × (6週/52週) ≒ **約340件**

**方法2（実測の層別外挿）:** 日付を伴う募集中は大規模層で0.8件/自治体（サンプル実測）。中小規模層を0.15件/自治体と仮定すると
200 × 0.8 + 1,259 × 0.15 = 160 + 189 = **約350件**

2つの方法が約350件で一致した。

> **系統A 同時募集中：全国で概ね 250〜500件**

### 外挿の限界

- 中小規模自治体の実測が松本市1件しかない。ここが2倍ずれれば全体が1.5倍ずれる。
- 「随時・通年・オンデマンド」型（横浜5件、川崎3件）は時点在庫として数えると水増しになる。上の推定からは除外している。
- 単純平均（1.6件 × 1,459 = 2,334件）は**大都市偏りを無視した過大推定**であり、採用していない。

| 板橋区産業振興公社 | **JSON** | `/cms-data/json/article-list.json` | 44件取得可・タグ付き。ただし**日付フィールドを持たない**ため詳細ページを開かないと開催日が分からない |

| 沖縄県産業振興公社 | RSS 2.0 | `/info/index.xml` | サイト全体の新着で**セミナー専用ではない**。15件しか遡れない |

**要注意（罠）:** 東京都よろず支援拠点はWordPressで、`<head>` 内に WP REST API のリンクタグ（`/wp-json/wp/v2/pages/27`）を出している。しかし実際に叩くと **HTTP 401 `{"code":"disable_rest_api","message":"REST API が無効化されています"}`** が返る。head のタグを見てAPIがあると判断してはいけない。

## 5. PDF依存が高く自動化が困難な機関

**これは想定より遥かに良い結果だった。**

**全18対象で、イベント告知そのものがPDFのみだった例は0件。** 検出されたPDFは以下のいずれかで、告知本体ではない。

- 申請書・様式（川崎市、川口市、松本市、高松市、那覇市）
- 要綱・注意事項・計画概要（横浜市、大阪市、高松市）
- パンフレット・施策集（川崎市）
- チラシ（松本市の創業スクールチラシ 3.26MB）— ただし**日時・会場・受講料の核心情報はHTML本文側にある**

PDF依存度が相対的に高い（中）と評価したのは **那覇市** と **高松市** の2件だが、これも「イベント告知がPDF」ではなく「制度説明がPDFに寄っている」という意味である。

> **示唆：** 告知本文のPDF化はこの領域ではボトルネックではない。真のボトルネックは**PDFではなく「そもそも日付が書かれていない」こと**である。系統A 10自治体のうち6自治体（大阪・福岡・那覇・高松・川口、および事実上の名古屋）が、日付を持つイベントを1件も掲載していなかった。

## 6. robots.txt / 利用条件で懸念がある機関

### robots.txt

**Disallowにより調査不可となった対象は0件。** 全18対象で、目的のパスはいずれもDisallowされていなかった。

ただし以下は運用上の注意が要る。

| 機関 | 懸念 |
|------|------|
| **福岡市** | Disallow行が**751行**。個別ページ単位で大量指定されている。対象パスは完全一致で該当しないが、リストが長大かつ流動的なため、**クロールのたびにrobots.txtを再取得して再照合する実装が必須**。 |
| **中小機構** | `gsa-crawler` と `msnbot` に対し **`Crawl-Delay: 5`** を明示。運営者が5秒間隔を要求している（今回の3秒より厳しい）。この機関を叩くなら5秒以上に設定すべき。 |
| **板橋区** | 区サイトが `/cgi-evt/`（イベント系CGI）と `/lib_cal/`（カレンダー）を**Disallow**。今回の対象パスは非該当だが、区のイベントカレンダー機能を将来使う場合は抵触する。また公社側の `/tag/` 一覧ページに **`<meta name="robots" content="noindex">`** が付いている（アクセス禁止ではないが、運営者が一覧の機械的な取り込みを歓迎していない兆候）。 |

robots.txtが**存在しない（404）**のは 横浜市・大阪市・松本市・高松市・川口市・関東経済産業局・大阪産業創造館・東京商工会議所（myeventサブドメイン）・板橋区産業振興公社 の9対象。禁止はされていないが、明示的な許諾でもない。

### 利用条件・著作権

**本文まで確認できたのは横浜市と川崎市の2件のみ。**残り8自治体はrobots.txtしか確認しておらず、規約本文は**未確認**である（JSONでは `reuse_note: "未確認"`）。これは本調査の積み残しであり、本格実装の前に潰す必要がある。

| 機関 | リンク | 転載・再利用 | 評価 |
|------|-------|------------|------|
| **大阪市** | — | 対象ページに **CC（クリエイティブコモンズ）ライセンス**表記 | **最良**。サンプル中で最も再利用しやすい |
| **横浜市** | 自由・報告不要 | 原則は無断複製・転用不可。ただし**「数値データ、簡単な表・グラフ等は著作権による保護の対象ではありませんので、自由に利用できます」と明記** | **良好**。セミナー一覧はまさに「簡単な表」に該当する |
| **川崎市** | 自由・許可依頼不要（出典明示） | 私的使用・引用を除き無断複製・転載を禁止。転載希望は**事前連絡かつ改変不可** | **要注意**。横浜のような表の除外規定がない |
| その他8自治体＋系統B各機関 | — | — | **未確認** |

> **法的な整理:** 開催日・会場・定員・料金といった**事実データそのものには著作権が及ばない**（横浜市が明文で認めている考え方）。リスクは事実の収集ではなく、**告知文の説明文をそのまま転載すること**にある。要約・リンク送客型で設計すれば、川崎市型の規約でも問題になりにくい。

## 8. この在庫でポータルが成立するか（所感）

### 成立する。ただし前提を1つ組み替える必要がある

当初の想定は「特定創業支援等事業の認定自治体1,459をベースに全国網を張る」だったと思われるが、**実測はその想定を支持しない。**

**理由1：自治体サイトの多くはイベント一覧ではなく事業カタログである。**
系統A 10自治体のうち、日付を持つイベントを掲載していたのは横浜・川崎・板橋・松本・名古屋の5自治体だけ。大阪・福岡・那覇・高松・川口の5自治体は**日付を1件も持っていなかった**。大阪市に至っては17か月未更新である。1,459自治体を回っても、その半分からは「事業名と実施機関名」しか得られない。

**理由2：クロール対象が1,459では済まない。**
自治体は実施を外部に委譲している。板橋区は区サイトに日程を一切持たず産業振興公社へ、名古屋市は名古屋産業振興公社へ、那覇市は6機関へ、高松市は商工会議所と香川県ポータルへ委譲していた。**実在庫を取りに行くと、対象は1,459自治体ではなく数千の商工会議所・公社・信用金庫・民間事業者に膨らむ。**

**理由3：一方で、支援機関側の在庫は十分厚い。**
東京商工会議所1機関で398件、うち「起業・創業」26件＋「補助金・助成金情報」26件。大阪産業創造館で60件。**上位機関を数十押さえるだけで、自治体1,459を回るより多くの在庫が、しかも遥かに安く取れる。**

### 推奨する設計

1. **フェーズ1：支援機関ファースト。** 東京商工会議所・大阪産業創造館・東京都中小企業振興公社・板橋区産業振興公社の4機関だけで、日付・会場・料金つきの在庫が数百件立つ。すべて easy ランクで、robots.txt上の障害もない。ここでポータルの体裁を作る。
2. **フェーズ2：日付を持つ自治体だけを足す。** 横浜・川崎型（構造化テーブル）を先に。日付を持たない自治体（大阪・福岡・那覇・高松・川口）は**イベントではなく「制度・支援機関ディレクトリ」として別スキーマで扱う**。無理にイベント化しない。
3. **フェーズ3：委譲先の商工会議所・公社を地域別に開拓。** ここが本当のロングテールで、コストもここに集中する。

### 数字で見た期待値

- 同時掲載可能件数（初期・支援機関中心）: **数百件オーダー**
- 系統A全国を完全網羅した場合の上乗せ: **同時募集中で250〜500件**（前提は§2参照）
- 合計しても**同時1,000件前後**が現実的な上限。「毎日何十件も新着が出るポータル」にはならない。**更新頻度ではなく網羅性と検索性で価値を出す設計**が要る。

### 最大のリスク

**受付状況が取れないこと。**明示的な受付状況フラグを持っていたのは、18対象中わずか3つ（大阪産業創造館の○△×、板橋区産業振興公社の受付中/受付終了、神奈川よろずの開催終了バッジ、ただし最後は手動設定）だけだった。関東経済産業局は終了したイベントを掲載したままで自動失効すらしない。

つまり**「募集中かどうか」はこちら側で日付から推定するしかない**。締切日すら書かれていないことが多い（東京商工会議所は398件中、明示的な締切日がほぼない）。**締切済みのイベントを募集中として見せてしまう事故が、このポータルの一番起きやすい品質問題になる。**保守的に落とす（不明なら「要確認」表示にする）方針を最初から入れておくべき。

2. **利用条件・著作権ページの本文確認（8自治体＋系統B全機関が未確認）。**本格実装前に必須。
